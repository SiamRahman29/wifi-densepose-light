# Guardian handoff — elderly-care detector

Goal: privacy-preserving room monitor (presence, respiration, fall; heartbeat TBD).
Hardware: 3x ESP32-S3 CSI nodes. Written 2026-08-26.

Read this before touching the sensing pipeline. It records findings that are NOT
obvious from the source and cost a full session to derive.

## Headline

The ESP32 boards work. The server's feature math does not. The "blob" seen in the
UI is noise, faithfully rendered.

## Evidence (MEASURED — reproducer: `motion-test.py`, output `motion-test-results.json`)

3-phase A/B/C test, 30 s each: still / moving / still, ~2030 frames per phase.

| Signal | Still A | Moving B | Still C | B : still |
|---|---|---|---|---|
| `motion_band_power` | 98.9 | 94.5 | 88.2 | 1.01 (blind) |
| `breathing_band_power` | 115.0 | 109.2 | 110.1 | 0.97 (blind) |
| `spectral_power` | 268.5 | 265.4 | 263.4 | 1.00 (blind) |
| raw CSI temporal variance, node 1 | 0.60 | 2.17 | 0.41 | 4.3x (works) |
| raw CSI temporal variance, node 2 | 0.27 | 1.22 | 0.28 | 4.4x (works) |
| raw CSI temporal variance, node 3 | 3.87 | 6.12 | 1.84 | 2.1x (unstable) |

Every named server feature is blind to a person walking and waving. Raw
per-subcarrier temporal variance separates cleanly at 4x on nodes 1 and 2.

Node health: node 3 disagrees with itself between the two still phases
(3.87 vs 1.84) — placement/multipath problem. Node 2 shows RSSI stdev ~6.2-6.8 dB
in ALL phases including still — bad link, unrelated to motion. Both need
placement work before trusting them.

## Four root causes, all in `v2/crates/wifi-densepose-sensing-server/src/main.rs`

1. **Band powers use the wrong axis** (~L2455-2470). `motion_band_power` and
   `breathing_band_power` split the *subcarrier array* in half and label the
   halves "motion" and "breathing". That is spatial frequency across the channel,
   dominated by static multipath from walls/furniture. Breathing is 0.1-0.5 Hz
   *in time*. These features cannot detect what they are named after at any SNR.
   The source comment even says "low spatial frequency".

2. **The working signal is masked** (~L2447). `compute_subcarrier_variances()`
   (~L2350) computes correct temporal variance — this is the 4x signal. Then:
   `let variance = intra_variance.max(temporal_variance);`
   intra ~= 100, temporal ~= 0.5-6. The `max()` discards the working detector
   every single frame.

3. **Sample rate is wrong by ~7x** (~L6800, L3197). Server hardcodes
   `1000.0 / 500.0` = 2 Hz. Firmware measures the real rate at 13-19 Hz. Every
   server-derived BPM is off by that factor. Worse: at an assumed 2 Hz, Nyquist
   is 1 Hz, so heart rate (1.0-1.7 Hz) is above the sampling limit — the server
   is arithmetically incapable of producing a real heartbeat.

4. **Window too short** (`FRAME_HISTORY_CAPACITY = 100`, L1597). 100 frames at
   ~15 Hz = 6.7 s. Resolving 0.1 Hz breathing needs one full 10 s cycle minimum,
   realistically 30-60 s.

Also: `estimate_breathing_rate_hz()` (L2231) builds its scalar series from the
mean amplitude across ALL subcarriers. Breathing appears in a subset; averaging
dilutes it and the mean tracks AGC. Needs subcarrier selection, not averaging.

## The part that already works — do not rewrite

`firmware/esp32-csi-node/main/edge_processing.c` is correct in approach:

- L1040-1055: measures the TRUE inter-frame sample rate from timestamps,
  EMA-smoothed, clamped 8-30 Hz. Comment references issue #985 (a fixed 10 Hz
  made 87 BPM read as 45).
- L1060-1067: designs real *temporal* biquad bandpass filters at 0.1-0.5 Hz
  (breathing) and 0.8-2.0 Hz (heart), re-tuning on >15% rate drift.
- Per-subcarrier phase extraction and unwrapping.

It already emits `edge_vitals_pkt_t` (`edge_processing.h:140`, 32 bytes, wire
format): presence/fall/motion flags, breathing BPM x100, heart BPM x10000, RSSI,
person count, motion energy, presence score.

**The fix is to trust this packet and delete the server's re-derivation**, not to
write new DSP.

## Heartbeat feasibility (CLAIMED — from literature, not measured here)

Breathing chest displacement ~5-12 mm. Heartbeat ~0.2-0.5 mm, roughly 30x
smaller, at 1-2 Hz where micro-movement dominates. Published ESP32 CSI HR results
generally need a motionless subject ~1 m from the antenna in a controlled room.
Across a bedroom with an elderly person shifting in a chair this will not hold up.
More ESP32s do not fix this — it is a sensor-physics limit, not a count limit.

Honest path: `edge_fused_vitals_pkt_t` (`edge_processing.h:174`, ADR-063) already
defines a 60 GHz mmWave fusion path with `mmwave_hr_bpm` / `mmwave_br_bpm`.
A ~$12 Seeed MR60BHA2 fuses into a packet the firmware already speaks.

Decision still open as of this handoff: add mmWave / CSI-only with hard gating /
drop heartbeat.

## Do not use the PyPI package

`wifi-densepose` 1.2.0 is this same repo. `pyproject.toml:187` declares
`include = ["wifi_densepose*", "src*"]` but there is no `src/` at repo root, so
the wheel is effectively one 4 KB `wifi_densepose/__init__.py`. That facade does
`sys.path.insert` on a sibling `v1/` dir that will not exist in a pip install.
Grep for ESP32 in the shipped Python: zero matches. It is the pose facade — the
layer that produced the blob — with the hardware support absent.
`archive/v1/` has ESP32 code but is marked `DEPRECATED.md`.

## Keep-list for the strip

The described system needs three things:

| Keep | Why |
|---|---|
| `firmware/esp32-csi-node/` | the working sensor, untouched |
| UDP vitals receive path in `main.rs` (`udp_receiver_task`) | ~200 lines that parse the 32-byte packet |
| a thin alert layer | "no breathing 60 s", "fall flag", "no presence 12 h" |

Not required: pose, densepose, `ui/` (3.4 MB), `dashboard/`, ~50 of 55 crates,
harness/brain/flywheel. It is a keep-list of three, not an audit of 353,640 lines.

The heartbeat decision only affects the alert layer — the last and smallest
piece — so the strip does not block on it.

## Fall detection — unsolved validation problem

The heuristic is buildable (large transient, then sustained post-event stillness,
no return to upright motion). Validating it is the hard part: you cannot test on
your grandmother. Needs a proxy — weighted cushion drops, or a younger person
falling onto a mattress — before any alert is trusted.
